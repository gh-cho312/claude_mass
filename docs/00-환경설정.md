# 00. 환경 설정

## 1. 하드웨어 요구사항

Isaac Sim 자체와 Isaac for Healthcare(i4h)는 요구사항이 다릅니다. **i4h가 훨씬 빡셉니다.**

| 항목 | Isaac Sim 단독 (이 과제집 Ex01~09) | Isaac for Healthcare (Ex10 이후) |
|---|---|---|
| GPU | RTX 계열, VRAM 8GB+ | **Compute Capability ≥ 8.6 (Ampere 이상)**, VRAM ≥ 24GB |
| GPU 제약 | — | **A100 / H100 불가** (RT Core가 없어 초음파 레이트레이싱 불가) |
| NVIDIA 드라이버 | 최신 권장 | ≥ 555.x |
| CUDA | — | ≥ 12.6, < 13.0 |
| RAM | 32GB 권장 | ≥ 64GB |
| 저장공간 | ~50GB | ≥ 100GB NVMe SSD |
| OS | Ubuntu 22.04/24.04, Windows | **Ubuntu 22.04 / 24.04 LTS (x86_64 전용)** |

> **핵심**: 초음파 시뮬레이션은 RT Core 기반 레이트레이싱을 씁니다. 데이터센터용
> A100/H100은 RT Core가 없어서 **i4h robotic_ultrasound가 돌아가지 않습니다.**
> RTX 4090 / RTX 6000 Ada / L40S 같은 Ada 세대 워크스테이션 GPU를 쓰세요.

### 확인 명령

```bash
# GPU 이름과 compute capability (8.6 이상이어야 i4h 가능)
nvidia-smi --query-gpu=name,compute_cap,memory.total --format=csv,noheader

# 드라이버 버전
nvidia-smi --query-gpu=driver_version --format=csv,noheader,nounits

# CUDA 툴킷
nvcc --version | grep release
```

또는 이 저장소의 스크립트를 쓰세요:

```bash
python tools/check_env.py
```

## 2. 버전 선택 — 어떤 Isaac Sim을 깔아야 하나

2026년 8월 기준 상황을 정리하면:

| 버전 | 상태 | 이 과제집 적합성 |
|---|---|---|
| **Isaac Sim 5.0** | i4h-workflows가 **고정(pin)한 버전**. Python 3.11 | i4h까지 갈 거면 **이걸 권장** |
| **Isaac Sim 5.1** | 안정 릴리스. 이 과제집 코드의 기준 | Ex01~09 학습용으로 최적 |
| **Isaac Sim 6.0** | GTC'26 **얼리 개발자 릴리스**. Newton 물리 백엔드 추가, 기존 PyTorch 기반 Core API를 Warp 기반 **Core Experimental API**로 대체 중 | ❌ 입문자 비권장 — API가 계속 바뀝니다 |

**추천**: 처음이라면 **Isaac Sim 5.1**로 Ex01~09를 하고, i4h로 넘어갈 때
i4h가 요구하는 **5.0**을 Docker 컨테이너로 따로 쓰세요. i4h는 어차피 컨테이너로
돌리는 게 기본이라 호스트의 Isaac Sim 버전과 충돌하지 않습니다.

> **6.0을 이미 깔았다면?** 이 과제집 코드는 대부분 그대로 돌지만,
> `isaacsim.core.api`가 deprecation 경고를 뱉을 수 있습니다.
> 경고는 무시해도 학습에는 지장 없습니다.

## 3. 설치 방법 3가지

### (A) pip 설치 — 가장 빠름, 입문자 권장

```bash
conda create -n isaacsim python=3.11 -y
conda activate isaacsim

pip install --upgrade pip
pip install "isaacsim[all,extscache]==5.1.0" --extra-index-url https://pypi.nvidia.com

# 첫 실행 (EULA 동의 프롬프트가 뜹니다)
isaacsim
```

> **파이썬 버전 주의**: Isaac Sim 5.x는 Python 3.11, 6.0(개발판)은 3.12를 씁니다.
> 설치가 `No matching distribution found`로 실패하면 십중팔구 파이썬 버전이 맞지 않는 것입니다.
> `pip index versions isaacsim --extra-index-url https://pypi.nvidia.com` 로
> 현재 환경에서 받을 수 있는 버전을 먼저 확인하세요.

- 장점: conda 환경 안에서 `python script.py`로 바로 실행 가능. 파이썬 패키지
  (numpy, torch, h5py 등) 추가 설치가 자유롭다.
- 단점: 첫 실행 시 셰이더 캐시 컴파일로 **10~20분** 걸릴 수 있음. (정상입니다. 기다리세요.)

이 과제집 실행:
```bash
conda activate isaacsim
python exercises/ex01_hello_phantom/solution.py --test
```

### (B) 바이너리(워크스테이션) 설치 — GUI 작업이 많다면

NVIDIA 개발자 사이트에서 Isaac Sim 압축본을 받아 풀면 디렉터리 안에
`isaac-sim.sh`(GUI)와 `python.sh`(스크립트 실행기)가 있습니다.

```bash
cd ~/isaacsim
./isaac-sim.sh                      # GUI 실행
./python.sh /경로/solution.py --test  # 스탠드얼론 스크립트 실행
```

- **주의**: `python.sh`는 Isaac Sim 내장 파이썬을 씁니다. 여기에 패키지를 추가하려면
  `./python.sh -m pip install h5py` 형태로 설치해야 합니다. 시스템 `pip`는 안 먹힙니다.

### (C) Docker — i4h로 넘어갈 때 사실상 필수

```bash
docker run --name isaac-sim --entrypoint bash -it --runtime=nvidia --gpus all \
  -e "ACCEPT_EULA=Y" -e "PRIVACY_CONSENT=Y" --network=host \
  -v ~/docker/isaac-sim/cache/kit:/isaac-sim/kit/cache:rw \
  -v ~/docker/isaac-sim/cache/ov:/root/.cache/ov:rw \
  -v $(pwd):/workspace:rw \
  nvcr.io/nvidia/isaac-sim:5.1.0
```

캐시 볼륨 마운트가 중요합니다. 안 하면 컨테이너 재시작마다 셰이더를 다시 컴파일합니다.

## 4. 첫 실행 검증

```bash
python - <<'PY'
from isaacsim import SimulationApp
app = SimulationApp({"headless": True})

from isaacsim.core.api import World
from isaacsim.storage.native import get_assets_root_path

world = World(stage_units_in_meters=1.0)
world.scene.add_default_ground_plane()
world.reset()
for _ in range(10):
    world.step(render=False)

print("assets root:", get_assets_root_path())
print("OK: Isaac Sim 정상 동작")
app.close()
PY
```

**성공 기준**
- `assets root:` 뒤에 `http://omniverse-content-production...` 같은 URL이 찍힘
- `OK: Isaac Sim 정상 동작` 출력
- 에러 없이 종료

**`assets root: None`이 나오면** — Nucleus 에셋 서버에 접근이 안 되는 상태입니다.
Ex03 이후 로봇/환경 에셋 로딩이 전부 실패합니다. 방화벽/프록시를 확인하거나,
에셋 팩을 로컬에 내려받고 아래처럼 환경변수를 잡아주세요.

```bash
export ISAAC_NUCLEUS_DIR=/local/path/to/Isaac
```

## 5. Isaac for Healthcare 별도 설치 (Ex10 이후)

```bash
git clone https://github.com/isaac-for-healthcare/i4h-workflows.git
cd i4h-workflows

# 통합 CLI로 워크플로우 실행 (컨테이너 자동 빌드)
./i4h run robotic_ultrasound full_pipeline --as-root
```

- 최초 빌드에 **10분 이상**, 이후 실행에도 Isaac Lab 초기화로 **2분 이상** 걸립니다.
  초기화 중에는 창이 멈춘 것처럼 보이는데 정상입니다.
- 워크플로우가 **RTI Connext DDS**를 프로세스 간 통신에 씁니다. 평가 라이선스를
  받아야 하고, 방화벽에서 UDP 7400~7401 / 멀티캐스트 239.255.0.1을 열어야 합니다.

```bash
sudo ufw allow in  proto udp to 239.255.0.1 port 7400:7401
sudo ufw allow out proto udp to 239.255.0.1 port 7400:7401
```

## 6. 자주 겪는 설치 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| 첫 실행이 10분 넘게 멈춤 | 셰이더 캐시 컴파일 | 정상. 기다리세요. 두 번째부터는 빠릅니다 |
| `ModuleNotFoundError: isaacsim` | conda 환경 미활성 또는 시스템 python 사용 | `conda activate isaacsim` 또는 `./python.sh` 사용 |
| `get_assets_root_path()` → `None` | Nucleus 접근 불가 | 네트워크/프록시 확인, 로컬 에셋 팩 + `ISAAC_NUCLEUS_DIR` |
| `Failed to create OptiX context` | 드라이버가 낮거나 RT Core 없는 GPU | 드라이버 업데이트, Ada 이상 GPU 사용 |
| GUI가 검은 화면 | 원격 접속(SSH/X11) 환경 | `--headless`로 실행하거나 Omniverse Streaming 사용 |
| `CUDA out of memory` | VRAM 부족 | 해상도/환경 개수 축소, `--headless` 사용 |
