# 01. 핵심 개념 — 이것만 알면 Isaac Sim이 읽힌다

Isaac Sim을 처음 열면 "Omniverse / USD / Kit / Isaac Lab / Replicator"가 한꺼번에
쏟아져서 뭐가 뭔지 모릅니다. 계층을 먼저 정리합시다.

---

## 1. 스택 구조

```
┌─────────────────────────────────────────────────────┐
│  Isaac for Healthcare (i4h)                         │  ← 의료 워크플로우 (초음파/수술/원격수술)
├─────────────────────────────────────────────────────┤
│  Isaac Lab           │  Replicator  │  ROS 2 Bridge │  ← 학습/합성데이터/통신 레이어
├─────────────────────────────────────────────────────┤
│  Isaac Sim  (isaacsim.core.api, isaacsim.sensors …) │  ← 로보틱스 API
├─────────────────────────────────────────────────────┤
│  Omniverse Kit  (omni.*)  +  PhysX  +  RTX 렌더러   │  ← 앱 프레임워크 / 물리 / 렌더링
├─────────────────────────────────────────────────────┤
│  OpenUSD  (pxr.Usd, UsdGeom, UsdPhysics …)          │  ← 씬 데이터 포맷
└─────────────────────────────────────────────────────┘
```

**읽는 법**: `omni.*`로 시작하면 Kit 레이어, `pxr.*`면 USD 레이어,
`isaacsim.*`이면 Isaac Sim 레이어입니다. 에러 메시지의 모듈 이름만 봐도
어느 층에서 터졌는지 알 수 있습니다.

## 2. USD — 씬은 "파일"이 아니라 "레이어 스택"이다

### Stage / Prim / Attribute

- **Stage**: 씬 전체. `omni.usd.get_context().get_stage()`로 얻습니다.
- **Prim**: 씬 그래프의 노드. `/World/Robot/panda_link0` 같은 **경로(prim path)**로 식별합니다.
  파일 시스템 경로처럼 생겼지만 파일이 아니라 씬 트리입니다.
- **Attribute**: prim이 가진 값. `xformOp:translate`, `physics:mass` 등.
- **Schema**: prim에 "이 prim은 강체다", "충돌체다" 같은 **역할**을 부여하는 인터페이스.
  `UsdPhysics.RigidBodyAPI`, `UsdPhysics.CollisionAPI`, `UsdSemantics.LabelsAPI` 등.

```python
from pxr import Usd, UsdGeom, UsdPhysics
import omni.usd

stage = omni.usd.get_context().get_stage()
prim = stage.GetPrimAtPath("/World/Phantom")
print(prim.GetTypeName())              # "Xform" / "Mesh" / "Cube" ...
print(prim.GetAttribute("xformOp:translate").Get())
print(prim.HasAPI(UsdPhysics.RigidBodyAPI))
```

### 참조(Reference) — 로봇을 씬에 "붙이는" 방법

로봇 USD를 씬에 넣을 때 복사하지 않고 **참조**합니다.

```python
from isaacsim.core.utils.stage import add_reference_to_stage
add_reference_to_stage(usd_path=".../franka.usd", prim_path="/World/Arm")
```

원본 USD가 바뀌면 참조한 씬도 같이 바뀝니다. 의료 에셋에서 이게 중요한 이유:
**환자 팬텀 하나를 여러 시나리오에서 참조**해두면, 팬텀을 개선했을 때
모든 시나리오가 자동으로 갱신됩니다.

### 단위(Units) — 의료에서 제일 많이 터지는 함정

USD stage는 `metersPerUnit` 메타데이터를 가집니다. Isaac Sim은 보통 **1.0 (미터)**로 씁니다.

```python
world = World(stage_units_in_meters=1.0)   # 1 unit = 1 meter
```

그런데 **의료 메쉬(STL/OBJ)는 대개 밀리미터 단위**입니다. 그대로 넣으면
간 하나가 1km짜리가 됩니다. 항상 스케일을 확인하세요.

```python
from isaacsim.core.utils.stage import get_stage_units
positions_in_meters / get_stage_units()   # stage 단위로 변환
```

→ Ex08에서 정면으로 다룹니다.

## 3. SimulationApp 수명주기 — 1번 함정

**스탠드얼론 스크립트의 import 순서에는 절대 규칙이 있습니다.**

```python
# ① 반드시 최상단. 이것 위에 isaacsim.* / omni.* import 금지
from isaacsim import SimulationApp
simulation_app = SimulationApp({"headless": False})

# ② SimulationApp 생성 "이후"에만 Isaac/Omni 모듈을 import할 수 있다
from isaacsim.core.api import World
from isaacsim.core.api.objects import DynamicCuboid
import omni.replicator.core as rep

...  # 씬 구성 + 시뮬레이션 루프

simulation_app.close()   # ③ 반드시 닫기
```

**왜?** `SimulationApp(...)`이 Kit 앱을 부팅하면서 확장(extension)을 로드합니다.
그 전에는 `isaacsim.core.api` 같은 모듈이 아예 존재하지 않습니다.
이 순서를 어기면 `ModuleNotFoundError` 또는 조용한 초기화 실패가 납니다.

**단, `argparse`, `numpy`, 표준 라이브러리는 위에 둬도 됩니다.**
실제 NVIDIA 공식 예제도 `argparse`를 `SimulationApp` 위에서 파싱합니다
(headless 여부를 인자로 받아야 하니까요).

```python
import argparse
parser = argparse.ArgumentParser()
parser.add_argument("--headless", action="store_true")
args, _ = parser.parse_known_args()

from isaacsim import SimulationApp
simulation_app = SimulationApp({"headless": args.headless})
```

## 4. World — 시뮬레이션 루프의 지휘자

```python
from isaacsim.core.api import World

world = World(stage_units_in_meters=1.0)
world.scene.add_default_ground_plane()
world.scene.add(DynamicCuboid(prim_path="/World/Tool", name="tool", ...))

world.reset()          # ← 물리 핸들 초기화. 이걸 호출해야 관절 제어가 먹는다
for _ in range(500):
    world.step(render=True)
```

### `world.reset()`을 언제 부르나 — 2번 함정

**`reset()` 전에는 `Articulation`의 물리 뷰(physics view)가 아직 없습니다.**

```python
arm = Articulation(prim_paths_expr="/World/Arm", name="arm")

arm.get_joint_positions()   # ❌ reset() 전 → None 또는 에러
world.reset()
arm.get_joint_positions()   # ✅ 정상
```

- `reset()` **전**에 할 수 있는 것: prim 추가, `set_world_poses()`로 초기 배치
- `reset()` **후**에만 되는 것: `get/set_joint_positions()`, `apply_action()`,
  `num_dof`, `dof_names`, 센서 읽기

### `step(render=True)` vs `render=False`

| | 물리 진행 | 렌더 | 용도 |
|---|:--:|:--:|---|
| `step(render=True)` | ✅ | ✅ | 눈으로 보며 디버깅, 카메라 캡처 |
| `step(render=False)` | ✅ | ❌ | headless 학습/벤치마크 (**훨씬 빠름**) |

카메라 이미지를 읽으려면 반드시 `render=True`여야 합니다. → Ex04

## 5. Prim 래퍼 — Single vs View, 3번 함정

Isaac Sim 5.x의 `isaacsim.core.prims`에는 두 계열이 있습니다.

```python
from isaacsim.core.prims import Articulation, RigidPrim, GeometryPrim
```

이들은 **뷰(view) 클래스**입니다. 즉 **여러 prim을 한 번에 배치(batch) 처리**합니다.
그래서 인자와 반환값에 **앞쪽 차원이 하나 더 붙습니다.**

```python
arm = Articulation(prim_paths_expr="/World/Arm", name="arm")
world.reset()

arm.get_joint_positions()            # shape (1, 9)  ← 배치 차원!
arm.set_joint_positions([[0.0]*9])   # 2중 리스트  ← 배치 차원!

# 여러 개를 와일드카드로 한 번에
views = Articulation(prim_paths_expr="/World/envs/*/Robot", name="robots")
views.get_joint_positions()          # shape (N, 9)
```

**초보자가 제일 많이 하는 실수**: `set_joint_positions([0, 0, 0, ...])`처럼
1차원 리스트를 넣고 shape 에러를 만나는 것입니다. **항상 `[[...]]`**로 감싸세요.

반면 `SingleArticulation`, `Franka`, `SingleManipulator` 같은 단일 객체 클래스는
배치 차원이 없습니다. 어느 쪽을 쓰는지 항상 확인하세요.

**제어 API도 갈립니다** (초보자가 두 번째로 많이 막히는 지점):

```python
# 배치 뷰 — get_articulation_controller()가 없다. AttributeError가 난다.
from isaacsim.core.utils.types import ArticulationActions          # 복수형
arm.apply_action(ArticulationActions(joint_positions=targets))     # (N, num_dof)

# 단일 — 컨트롤러를 거친다
from isaacsim.core.utils.types import ArticulationAction           # 단수형
single.get_articulation_controller().apply_action(
    ArticulationAction(joint_positions=target))                    # (num_dof,)
```

그리고 **모션 생성 모듈(`RmpFlow`, `ArticulationKinematicsSolver`)은
`SingleArticulation`만 받습니다.** 배치 뷰를 넘기면 내부에서 실패합니다.

## 6. 좌표계와 회전

- Isaac Sim의 기본 up-axis는 **Z-up**입니다. (많은 CAD/의료 툴은 Y-up이라 변환이 필요)
- 회전은 **쿼터니언 `(w, x, y, z)`** 순서입니다. scipy는 `(x, y, z, w)`라 **순서가 다릅니다.**

```python
import isaacsim.core.utils.numpy.rotations as rot_utils
import numpy as np

q = rot_utils.euler_angles_to_quats(np.array([0, 90, 0]), degrees=True)  # (w,x,y,z)
```

## 7. Replicator — 합성 데이터의 문법

Replicator는 **선언형**입니다. `with` 블록으로 "언제(trigger) 무엇을(modify)
어떻게(distribution) 바꿀지"를 등록해두고, `rep.orchestrator.step()`으로 실행합니다.

```python
import omni.replicator.core as rep

camera = rep.create.camera()
rp = rep.create.render_product(camera, (640, 480))

rgb = rep.AnnotatorRegistry.get_annotator("rgb")
seg = rep.AnnotatorRegistry.get_annotator("semantic_segmentation")
rgb.attach(rp); seg.attach(rp)

with rep.trigger.on_frame():
    with rep.get.prims(semantics=[("class", "scalpel")]):
        rep.modify.pose(position=rep.distribution.uniform((-0.2,-0.2,0.8), (0.2,0.2,0.9)))

rep.orchestrator.step(rt_subframes=4)      # 1 프레임 캡처
data = rgb.get_data()                       # HxWx4 uint8
```

**중요**: `with` 블록은 **실행이 아니라 등록**입니다. 블록 안에 `print()`를 넣어도
매 프레임 찍히지 않습니다. → Ex07

## 8. 시맨틱 라벨 — 5.x에서 API가 바뀜, 4번 함정

세그멘테이션/바운딩박스 정답을 얻으려면 prim에 **시맨틱 라벨**을 붙여야 합니다.
Isaac Sim 5.x에서 이 API가 교체되었습니다.

```python
from isaacsim.core.utils.semantics import add_labels, get_labels

# ✅ 5.x 권장 — UsdSemantics.LabelsAPI
add_labels(prim, labels=["scalpel"], instance_name="class")

# ⚠️ deprecated — 옛 SemanticsAPI (경고 발생)
from isaacsim.core.utils.semantics import add_update_semantics
add_update_semantics(prim, "scalpel", "class")
```

인터넷의 오래된 튜토리얼은 대부분 `add_update_semantics`를 씁니다. 동작은 하지만
경고가 뜨고, 앞으로 제거될 예정입니다. **새 코드는 `add_labels`를 쓰세요.**

## 9. 초보자가 밟는 함정 10선 (요약)

| # | 함정 | 해결 |
|:--:|---|---|
| 1 | `SimulationApp` 전에 `isaacsim.*` import | 무조건 `SimulationApp` 생성 후 import |
| 2 | `world.reset()` 전에 관절 읽기/쓰기 | `reset()` 이후에 접근 |
| 3 | 뷰 클래스에 1차원 배열 전달 | `[[...]]`로 배치 차원 추가 |
| 3b | 배치 뷰에 `get_articulation_controller()` 호출 | 뷰는 `apply_action(ArticulationActions(...))` |
| 4 | `add_update_semantics` 사용 | `add_labels`로 교체 |
| 5 | 의료 메쉬 단위(mm) 그대로 임포트 | `metersPerUnit` 확인 후 0.001 스케일 |
| 6 | `step(render=False)`인데 카메라 읽기 | 캡처 프레임만 `render=True` |
| 7 | 복잡한 장기 메쉬에 `convexHull` 충돌체 | `convexDecomposition` 또는 `sdf` 사용 |
| 8 | 쿼터니언 순서 `(x,y,z,w)`로 착각 | Isaac은 `(w,x,y,z)` |
| 9 | `simulation_app.close()` 누락 | `try/finally`로 감싸기 |
| 10 | 첫 실행이 느리다고 강제 종료 | 셰이더 캐시 컴파일 중. 10~20분 기다리기 |

## 10. 디버깅 팁

```python
# 씬 트리 전체 출력 — "내 prim이 어디 붙었지?"
import omni.usd
for p in omni.usd.get_context().get_stage().Traverse():
    print(p.GetPath(), p.GetTypeName())

# 관절 이름과 인덱스 확인 — DOF 순서는 USD 정의 순서지 이름 순이 아니다
print(arm.dof_names)
print(arm.num_dof)

# 물리 디바이스 확인 (CPU/GPU)
from isaacsim.core.simulation_manager import SimulationManager
SimulationManager.set_physics_sim_device("cuda")   # 또는 "cpu"
```

GUI에서는 **Window → Stage**로 씬 트리를, **Window → Property**로 선택한 prim의
어트리뷰트를 봅니다. 스크립트로 안 되는 게 있으면 GUI에서 먼저 손으로 해보고
어떤 어트리뷰트가 바뀌는지 관찰하는 게 가장 빠른 학습법입니다.
