# 04. i4h 설치 가이드 (RTX 3090)

> 과제집(Ex 01~10)과 [03. Isaac for Healthcare로 넘어가기](03-i4h-연결.md)를
> 마친 뒤 읽으세요. 실제 `robotic_surgery` 워크플로를 데스크탑에 올리는 단계입니다.

Ubuntu + Isaac Sim 5.0 이 이미 설치된 데스크탑에서
**i4h robotic_surgery**(ORBIT-Surgical 후계자)와
**Open-H-Embodiment** 데이터셋을 사용하기 위한 절차입니다.

---

## 0. 왜 ORBIT-Surgical 원본을 설치하지 않는가

i4h `robotic_surgery` 워크플로 README에 명시되어 있습니다:

> "This workflow originated from the **ORBIT-Surgical** framework."

NVIDIA가 ORBIT-Surgical을 최신 스택으로 포팅해 유지보수하는 것이
`robotic_surgery` 워크플로입니다. 원본은 두 세대 뒤처져 있습니다.

| | 원본 ORBIT-Surgical | i4h robotic_surgery |
|---|---|---|
| Isaac Sim | 4.1.0 | **5.0.0** |
| Isaac Lab | 1.0.0 | **2.3.0** |
| Python | 3.10 | **3.11** |

세 항목이 모두 어긋나므로, 원본을 현재 환경에 얹으면 충돌합니다.
논문을 정확히 재현해야 하는 경우가 아니면 원본은 건너뛰세요.

## 1. 사전 점검

```bash
./scripts/00_preflight.sh
```

RTX 3090 기준 요구사항 대조 결과를 출력합니다.

| 요구 | RTX 3090 | 비고 |
|---|---|---|
| VRAM ≥ 24GB | 24GB | 딱 맞음, 여유 없음 |
| Compute Capability ≥ 8.6 | 8.6 (Ampere) | 딱 맞음 |
| 드라이버 ≥ 535.129.03 | 확인 필요 | |
| 디스크 ≥ 100GB NVMe | **확인 필요** | 가장 흔한 실패 지점 |
| RAM ≥ 32GB | 확인 필요 | |
| Ubuntu 22.04 / 24.04 | | |

`[FAIL]` 이 하나라도 나오면 먼저 해결하고 진행하세요.

### 디스크가 부족하다면

- **Docker 대신 Conda 설치를 쓰세요** — 컨테이너 이미지 용량이 빠집니다
- `config/env.sh` 의 `I4H_ROOT` 를 여유 있는 파티션으로 지정
- Open-H-Embodiment 데이터는 `OPENH_DATA_DIR` 로 별도 디스크에

## 2. 설정 파일 준비

```bash
cp config/env.example.sh config/env.sh
$EDITOR config/env.sh      # 경로를 본인 환경에 맞게 수정
```

`config/env.sh` 는 `.gitignore` 되어 있어 로컬 경로를 담아도 안전합니다.

---

## 3. robotic_surgery 설치

```bash
./scripts/01_install_robotic_surgery.sh
```

수행 내용:
1. `i4h-workflows` 저장소 클론
2. conda 환경 `robotic_surgery` 생성 (Python 3.11)
3. `tools/env_setup_robot_surgery.sh` 실행 — **40~60분 소요**
4. `PYTHONPATH` 등록

> 기존에 다른 i4h 워크플로(초음파 등)를 쓰고 계시면
> **conda 환경을 새로 파는 걸 권합니다.** 워크플로마다 의존성이 달라
> 한 환경에 몰아넣으면 충돌합니다.

설치 후 매 세션마다:

```bash
conda activate robotic_surgery
export PYTHONPATH=$I4H_ROOT/workflows/robotic_surgery/scripts:$PYTHONPATH
```

## 4. 동작 확인

```bash
./scripts/02_smoke_test.sh              # 태스크 목록
./scripts/02_smoke_test.sh reach_psm    # 가장 가벼운 것부터
```

### 사용 가능한 태스크

| 태스크 | 설명 |
|---|---|
| `reach_psm` | 단일 PSM 리칭 — **여기서 시작** |
| `reach_dual_psm` | 양팔 협응 |
| `reach_star` | STAR 로봇 |
| `lift_block` | 블록/페그 트랜스퍼 |
| `lift_needle` | 봉합침 들어올리기 |
| `lift_needle_organs` | 장기 포함 수술실 씬 (가장 무거움) |

**RL 환경 ID**: `Isaac-Reach-PSM-v0`, `Isaac-Reach-PSM-Play-v0`,
`Isaac-Lift-Needle-PSM-IK-Rel-v0`

첫 실행은 에셋 다운로드 때문에 5~10분 걸립니다.

## 5. num_envs 상한 찾기 ★ 3090에서 가장 중요

README 예시는 `--num_envs 4096` 인데, 이건 여유 있는 GPU 기준입니다.
**24GB 카드에서 그대로 쓰면 학습 중반에 OOM이 납니다.**

```bash
./scripts/03_find_max_envs.sh
```

256 → 512 → 1024 → 2048 → 4096 순으로 짧은 학습을 돌리며
VRAM 피크를 실측하고, 상한(기본 85%)을 넘거나 OOM이 나면 멈춥니다.

결과를 `config/env.sh` 에 반영하세요:

```bash
export TRAIN_NUM_ENVS=1024   # 측정값
```

> **태스크마다 상한이 다릅니다.** 변형체가 들어가는
> `lift_needle_organs` 는 훨씬 낮게 잡아야 합니다.
> 태스크를 바꾸면 `--task` 옵션으로 다시 측정하세요.

### VRAM을 아끼는 방법 (효과 순)

1. **학습은 항상 `--headless`** — `04_train_rl.sh` 가 자동으로 붙입니다
2. **학습 중 브라우저/IDE 닫기** — 3090에서는 1~2GB 차이가 실효적
3. **모니터를 내장 그래픽(iGPU)으로 이전** — BIOS에서 iGPU 활성화 후
   메인보드 출력에 연결하면 24GB를 온전히 씁니다. **가장 확실**
4. TTY(`Ctrl+Alt+F3`) 전환 후 데스크탑을 내리고 학습

---

## 6. 학습

```bash
# 별도 터미널에서 모니터링
./scripts/gpu_monitor.sh

# 학습
./scripts/04_train_rl.sh
./scripts/04_train_rl.sh --task Isaac-Lift-Needle-PSM-IK-Rel-v0 --envs 512
```

학습된 정책 재생:

```bash
./scripts/04_train_rl.sh --play
```

### 열 관리

3090은 TDP 350W입니다. RL 학습은 GPU를 45분 이상 100%로 붙잡습니다.
83°C를 넘으며 클럭이 떨어지면(thermal throttle) 오히려 느려집니다.

```bash
sudo nvidia-smi -pl 300    # 350W -> 300W. 온도 개선폭이 성능 손실보다 큼
```

## 7. Open-H-Embodiment (선택)

**Isaac Sim과 무관합니다.** 시뮬레이터 확장이 아니라 LeRobot 포맷
데이터셋 파일 묶음입니다. 요구 Python 버전도 달라 별도 환경을 씁니다.

```bash
./scripts/10_install_openh.sh     # conda 환경 openh (Python 3.12) + lerobot
conda activate openh
```

### 반드시 탐색부터

780시간 규모라 통째로 받으면 디스크가 감당하지 못합니다.

```bash
# 1) 무엇이 들어있는지 확인 (다운로드 없음)
python tools/explore_openh.py

# 2) 스트리밍으로 프레임 구조 확인 (다운로드 없음)
python tools/explore_openh.py --sample

# 3) 서브셋 목록과 각 용량
python tools/download_openh_subset.py --list

# 4) 용량 계산만
python tools/download_openh_subset.py --include 'data/chunk-000/*' --dry-run

# 5) 실제 다운로드
python tools/download_openh_subset.py --include 'data/chunk-000/*'
```

> **확인 필요**: HuggingFace에 공개된 v1의 정확한 포맷과 디렉터리 구조는
> 데이터셋 카드에서 직접 확인하세요. GitHub에 기술된 v2 스펙
> (LeRobot v3.0)과 다를 수 있습니다. `explore_openh.py` 가 포맷을
> 자동 판정해 알려줍니다.
