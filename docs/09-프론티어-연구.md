# 09. 지금 장비의 천장과 그 너머

> [08. 차시별 커리큘럼](08-차시별-커리큘럼.md)의 **15차시** 자료입니다.
> 1~14차시를 마쳤다면, 자기 환경으로 할 수 있는 것과 없는 것의 경계가
> 어렴풋이 보일 것입니다. 이 문서는 그 경계를 **숫자로** 확정합니다.

---

## 1. RTX 3090으로 할 수 없는 것

### VRAM의 벽

| 모델 | 필요 VRAM | RTX 3090 (24GB) |
|---|---|---|
| OpenVLA (7B) 추론 | 단일 H100(80GB)에 적재 | 양자화 없이는 어려움 |
| OpenVLA LoRA 파인튜닝 | H100 80GB 1장 | 4-bit 양자화 + 짧은 시퀀스로 제한적 |
| **π₀.₅** | **H100 2장 + 모델 병렬** | ❌ 불가 |
| OpenVLA-OFT 학습 | A100/H100 80GB **8장** | ❌ 불가 |

정리하면, **VLA 정책을 처음부터 학습하는 것은 3090으로 불가능**합니다.
LoRA 파인튜닝조차 80GB 카드를 기준으로 설계되어 있습니다.

### GPU 시간의 벽

| 작업 | 규모 |
|---|---|
| GR00T N1-2B 사전학습 | **약 50,000 H100 GPU-시간**, 단일 모델에 최대 1,024 GPU |
| OpenVLA-OFT 학습 | 8×H100로 50K~150K 스텝, **1~2일** |
| FLOWER (효율 지향) | 200 H100 GPU-시간 |
| OpenVLA LoRA (10K 스텝) | H100 80GB 1장에서 **4~6 GPU-시간** |

50,000 H100-시간을 3090 한 장으로 환산하면 **수 년** 단위입니다.
(H100은 3090 대비 학습 처리량이 대략 한 자릿수 배 빠르고, 그 전에 VRAM에서
막힙니다.)

### 그럼 3090으로 무엇을 하는가

**할 수 있는 것 — 12~14차시에서 이미 했습니다:**

- 시뮬레이션 환경 개발과 태스크 설계
- **소규모 RL 학습** (PPO, state-based, num_envs 수백~수천) ← 12차시
- 공개 데이터셋 분석·시각화·포맷 변환 ← 13차시
- 궤적 재생과 정합 ← 14차시
- 합성 데이터 생성 ← 7차시
- 소형 VLA(SmolVLA 등) 추론과 제한적 파인튜닝

**못 하는 것:**

- 7B급 VLA 사전학습·전체 파인튜닝
- 대규모 비전 기반 RL (렌더링 포함 수천 환경)
- 월드 모델 학습

> **핵심**: 3090은 *만들고 검증하는* 장비이지 *스케일링하는* 장비가 아닙니다.
> 스케일이 필요해지는 시점에 클라우드 H100을 시간 단위로 빌리는 것이
> 현실적입니다. LoRA 파인튜닝 한 번이 H100 4~6시간이면, 그건 살 만한 비용입니다.

## 2. 지금 프론티어에서 벌어지는 일

2025~2026년에 이 분야가 실제로 어디까지 갔는지, 대표 결과 셋으로 봅니다.

### ① SRT-H — 자율 수술의 현재 최고 수준

**Johns Hopkins**, *Science Robotics* (2025)

담낭절제술의 **클리핑·커팅 구간**을 사람 개입 없이 완전 자율로 수행.
ex vivo 돼지 담낭 8건에서 **성공률 100%**.

구조가 중요합니다:

```
상위 정책 (언어 공간에서 계획)
   ↓  "clip the cystic duct" 같은 태스크 수준 지시 + 교정 지시
하위 정책 (궤적 생성)
```

**상위 계획을 언어로 한다**는 게 핵심입니다. 그래서 실패했을 때 "다시 잡아라"
같은 교정 지시를 낼 수 있고, 이것이 논문이 강조하는 **오류 복구 능력**입니다.
14차시에서 확인한 "실기기 궤적 재생으로는 복구가 안 된다"는 문제에 대한
현재의 답이 이것입니다.

> **13차시와 이어집니다**: ImitateCholec은 같은 JHU 랩이 같은 시술 구간
> (클리핑·커팅, 17개 세부 태스크)에서 dVRK로 모은 데이터셋입니다.
> 여러분이 다운로드할 수 있는 데이터가 이 계열 연구의 토대입니다.

**한계도 분명합니다**: 전체 담낭절제술이 아니라 한 구간이고, ex vivo 돼지
조직입니다. 살아있는 환자가 아닙니다.

### ② Surgical Embodied Intelligence — 시뮬레이터에서 실기기로

*Science Robotics* (2025)

복강경 수술 로봇용 오픈소스 시뮬레이터를 만들고, 시뮬레이션에서 학습한 정책을
**zero-shot으로 실기기에 전이**. 여러 복강경 플랫폼에 걸친 멀티태스크 수행을
보였습니다.

방향이 명확합니다 — **다양한 시뮬레이터와 데이터셋으로 학습한 멀티태스크·
멀티모달 VLA가 문맥을 넘어 zero-shot 전이**. 12차시에서 여러분이 돌린
시뮬레이션 학습의 확장판입니다.

### ③ Open-H-Embodiment / GR00T-H — 파운데이션 모델화

**NVIDIA + 50여 기관** (2026)

780시간, 20개 로봇 플랫폼, 33개 태스크 계열, **5종 환경(디지털 시뮬레이션 ~
실제 임상 시술)**. 여기에 최초의 오픈 의료 VLA인 **GR00T-H**와 액션 조건부
월드 모델 **Cosmos-H-Surgical**이 딸려 나왔습니다.

성능은 아직 초기입니다. 구조화된 봉합 벤치마크에서 **완전 자동 완수 25%**
(다른 베이스라인은 전부 0%), 29단계 ex vivo 봉합 시퀀스에서 평균 65% 성공.

> 숫자가 낮아 보이지만, **비교 대상이 0%**라는 점이 중요합니다.
> 이 분야는 지금 "되기 시작한" 단계입니다.

## 3. 자율성 레벨 — 지금 어디쯤인가

Yang 등이 *Science Robotics*에 제안한 6단계가 표준으로 쓰입니다.

| 레벨 | 정의 | 현재 상황 |
|:--:|---|---|
| **0** | 자율성 없음 — 텔레오퍼레이션 | da Vinci 기본 동작 |
| **1** | 로봇 보조 — 기계적 가이드, 사람이 계속 제어 | **FDA 승인 수술 로봇의 86%** |
| **2** | 태스크 자율 — 하나의 수술 태스크를 자율 수행 | SRT-H가 여기 (연구 단계) |
| **3** | 조건부 자율 — 계획하고 실행 중 갱신 | FDA 승인 로봇의 6% |
| **4** | 고도 자율 — 태스크 **시퀀스**를 자율 수행 | 연구 초기 |
| **5** | 완전 자율 — 사람 없이 전체 수술 | 미도달 |

**읽는 법**: 임상 현장의 압도적 다수는 여전히 Level 1입니다. 연구 최전선이
Level 2를 ex vivo에서 막 달성한 상태이고, Level 4~5는 기술 문제만이 아니라
규제·책임 문제이기도 합니다.

> 14차시에서 "니들이 안 잡히는" 것을 본 경험이 이 표를 이해하는 데 도움이
> 됩니다. Level 2 하나를 ex vivo에서 해내는 데 얼마나 많은 것이 필요한지
> 감이 오실 겁니다.

## 4. 미해결 과제 — 여기가 연구 주제입니다

### ① in vivo 데이터의 부재

공개된 액션 데이터는 **거의 전부 ex vivo**(돼지 간, 인공 팬텀)입니다.
살아있는 조직은 출혈·탄성·호흡 움직임이 전부 다릅니다.

규제상 환자 데이터는 사실상 공개되지 않습니다. IRB, HIPAA, 국내
개인정보보호법·의료기기법이 걸립니다. **데이터 부족이 기술 문제가 아니라
제도 문제**인 대표 사례입니다.

### ② 크로스 임베디먼트

dVRK 7-DoF 리스트, Versius, MIRA는 액션 공간이 서로 호환되지 않습니다.
Open-H-Embodiment가 20기종을 묶은 이유이자, 여전히 어려운 이유입니다.

> 8차시에서 겪은 단위·좌표계 문제의 확장판입니다. 기종이 20개면 그 문제가
> 20배가 아니라 조합적으로 늘어납니다.

### ③ 실패 복구

시연 데이터는 거의 **성공 궤적만** 담습니다. 정상 궤도를 벗어난 상태
(물건을 떨어뜨림, 팔이 어정쩡한 자세)는 학습 분포 밖입니다.

현재의 대응:
- SRT-H의 언어 기반 교정 지시
- Open-H-Embodiment의 **실패·복구 스플릿 별도 제공**
- RL 파인튜닝으로 실제 실패를 겪게 하기

### ④ 접촉과 변형의 시뮬레이션

**14차시에서 직접 확인한 문제입니다.** 시뮬레이터의 장기 모델과 실제 조직은
형상·물성이 다릅니다. 궤적을 재생해도 접촉·변형이 어긋납니다.

FEM(ORBIT-Surgical)이든 MPM(SurRoL)이든 실제 조직의 비선형·이방성·점탄성을
충분히 재현하지 못합니다. 여기에 **촉각·힘 피드백 데이터가 거의 없다**는
문제가 겹칩니다.

### ⑤ 장기 시퀀스 (Long-horizon)

Level 2(태스크 하나)에서 Level 4(태스크 시퀀스)로 가는 벽입니다.
29단계 봉합 시퀀스에서 평균 65%라는 숫자는, 각 단계가 아무리 좋아도
곱해지면 급격히 떨어진다는 뜻입니다.

### ⑥ 안전성·검증·규제

- 정책이 언제 실패할지 **미리 알 수 있는가** (uncertainty estimation)
- 안전 범위를 벗어나는 명령을 어떻게 차단하는가
- 학습 기반 시스템을 어떻게 **인허가**받는가 — 결정론적이지 않은 소프트웨어의
  의료기기 승인은 아직 정립 중입니다

## 6. 다음에 무엇을 할 것인가

### 지금 장비로 시작할 수 있는 것

| 방향 | 왜 3090으로 가능한가 |
|---|---|
| **시뮬레이션 환경·태스크 설계** | 렌더링만 감당하면 됨. 7~10차시 연장선 |
| **데이터셋 분석·큐레이션 도구** | GPU 거의 불필요. 13차시 연장선 |
| **소규모 RL로 특정 스킬 학습** | state-based면 3090으로 충분. 12차시 연장선 |
| **크로스 데이터셋 포맷 변환기** | 14차시에서 시작한 것. 실제로 없어서 필요한 도구 |
| **평가 지표·벤치마크 설계** | 계산보다 설계 문제 |

### 스케일이 필요해지면

1. **클라우드 H100을 시간 단위로** — LoRA 파인튜닝 한 번이 4~6시간
2. **효율 지향 모델 선택** — SmolVLA, FLOWER처럼 작게 설계된 것
3. **연구실/기관 클러스터** — 사전학습급은 이쪽

### 주제 선정 기준

15차시 산출물로 관심 주제 3개를 고를 때, **최소 하나는 지금 장비로 시작
가능한 것**으로 잡으세요. 위 표의 다섯 방향 중 넷은 **도구가 없어서 실제로
필요한 것**들입니다. 프론티어는 큰 모델만 있는 게 아니라, 그 모델을 쓸 수
있게 만드는 주변 도구도 부족합니다.

## 검증 상태

이 문서의 수치와 결과는 공개 논문·저장소 문서에서 교차 확인했습니다. 다만:

- **Science Robotics 원문은 구독이 필요해 초록과 2차 자료로 확인**했습니다.
  SRT-H의 100% 성공률, 자율성 레벨 정의, FDA 통계가 여기 해당합니다.
  인용하실 때는 원문을 직접 확인하세요.
- GPU 시간·VRAM 수치는 각 모델의 공개 문서 기준이며, 실제로는 배치 크기와
  시퀀스 길이에 따라 크게 달라집니다.
- 이 분야는 빠르게 움직입니다. 6개월 뒤에는 숫자가 달라져 있을 것입니다.
