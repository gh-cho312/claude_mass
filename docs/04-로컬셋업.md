# 04. 로컬 PC 셋업 (실습 + 시뮬레이터 전체)

이 문서는 **여러분의 로컬 리눅스 PC(RTX GPU 장착)**에 실습 환경 일체를 까는 절차입니다.
세 덩어리를 **서로 다른 격리 환경**에 설치합니다 — 파이썬/의존성이 충돌하기 때문입니다.

| 대상 | 무엇 | 환경 | 파이썬 | GPU |
|---|---|---|:--:|:--:|
| **A. 이 과제집(Ex01~10)** | Isaac Sim 5.1 학습 | conda `isaacsim` | 3.11 | RTX(RT Core) 필요 |
| **B. SurRoL** | 수술로봇 RL 시뮬(dVRK, PyBullet) | conda `surrol` | 3.7 | 불필요(CPU 가능) |
| **C. i4h 워크플로우** | Isaac for Healthcare | **Docker 컨테이너** | (컨테이너 내부) | RTX 24GB+ |

> ⚠️ **A와 B를 같은 환경에 섞지 마세요.** Isaac Sim은 Python 3.11, SurRoL(원본)은 Python 3.7 +
> TensorFlow 1.14를 씁니다. 한 환경에 넣으면 반드시 깨집니다.

> ℹ️ 원격/클라우드 세션(예: Claude Code on the web)의 컨테이너에는 GPU가 없어 Isaac Sim이
> 실행되지 않습니다. **아래 절차는 반드시 실제 GPU가 달린 로컬 PC에서** 수행하세요.

---

## 0. 사전 준비물

1. **Ubuntu 22.04 / 24.04 (x86_64)**
2. **NVIDIA 드라이버 ≥ 555.x** — `nvidia-smi` 로 확인
3. **Miniconda** — 없으면 `setup_local.sh` 가 **자동 설치**합니다(아래 A-1). 손수 깔려면:
   ```bash
   wget https://repo.anaconda.com/miniconda/Miniconda3-latest-Linux-x86_64.sh
   bash Miniconda3-latest-Linux-x86_64.sh
   # 셸 다시 열기 (conda init 반영)
   ```
   > 자동 설치를 원치 않으면 `bash setup_local.sh --no-install-conda` 로 끌 수 있습니다.
4. **git** (`sudo apt install -y git`)
5. i4h까지 갈 거면 **Docker + NVIDIA Container Toolkit**

먼저 GPU/드라이버부터 점검:
```bash
python tools/check_env.py
```

## A. 이 과제집 + Isaac Sim 5.1

### A-1. 자동 (권장)

저장소 루트에서 한 줄:
```bash
bash setup_local.sh
```
이게 `isaacsim` 환경 생성 → Isaac Sim 5.1 설치 → `h5py` 설치 → `check_env.py` 검증까지 합니다.
SurRoL/i4h까지 한 번에 하려면:
```bash
bash setup_local.sh --with-surrol --with-i4h
```

### A-2. 수동 (스크립트가 막히면)

```bash
conda create -n isaacsim python=3.11 -y
conda activate isaacsim
pip install --upgrade pip
pip install "isaacsim[all,extscache]==5.1.0" --extra-index-url https://pypi.nvidia.com
pip install -r requirements.txt         # h5py (Ex10 데이터셋 저장용)
python tools/check_env.py
```

첫 과제로 검증:
```bash
python exercises/ex01_hello_phantom/solution.py --test
```
> 첫 실행은 셰이더 캐시 컴파일로 **10~20분** 걸릴 수 있습니다(정상). 자세한 설치 방법·문제해결은
> [00-환경설정.md](00-환경설정.md)를 보세요.

### A-3. GUI 편집기 열기 / 클릭 아이콘 만들기

pip 설치는 **바탕화면 아이콘을 만들지 않습니다.** GUI 3D 편집기는 터미널에서 엽니다:
```bash
conda activate isaacsim
isaacsim isaacsim.exp.full.kit        # 또는 그냥 isaacsim
```
> 첫 실행은 EULA 동의 + 확장 다운로드로 **10분 이상** 걸립니다(각 experience 최초 1회).

클릭으로 여는 앱 메뉴/바탕화면 아이콘을 원하면:
```bash
bash tools/make_desktop_launcher.sh   # ~/.local/share/applications 에 .desktop 생성
```
생성 후 앱 메뉴에서 "Isaac Sim" 검색 → 클릭. (바탕화면 아이콘이 회색이면 우클릭 → "실행 허용".)

### A-4. 첫 실행은 **헤드리스로 예열**하세요 (권장)

GUI로 첫 실행을 하면 창이 그려지지 않는 동안 우분투가 "응답 없음"으로 판단해
**중단하기/기다리기** 대화상자를 반복해서 띄웁니다. 창 없이 먼저 돌리면 이 문제가 아예 없고,
진행 상황이 터미널에 그대로 보입니다.

```bash
conda activate isaacsim
cd ~/claude_mass
python examples/minimal_control.py        # GUI 없음 → 창이 얼지 않음
```

`최종 높이 z = 0.050 m` 가 출력되면 **확장·셰이더 캐시가 완성된 것**입니다.
그 다음부터 GUI(`isaacsim isaacsim.exp.full.kit`)는 훨씬 빨리 뜹니다.

## B. SurRoL (수술로봇 학습 시뮬레이터)

**SurRoL**은 da Vinci Research Kit(dVRK) 호환, PyBullet 기반의 **수술로봇 강화학습 플랫폼**입니다
(IROS'21, med-air/SurRoL, MIT). `NeedleReach-v0`, `NeedlePick-v0`, `PegTransfer-v0` 같은
수술 태스크를 Gym 스타일 API로 제공합니다. Isaac Sim과는 **완전히 별개 생태계**입니다.

> ⚠️ **솔직한 난이도 안내**: SurRoL은 "가볍게 한 번 보기"에 적합하지 않습니다.
> 실제 저장소를 확인한 결과 아래 마찰 요인들이 있습니다. 시간을 각오하세요.

### B-0. 먼저 알아야 할 실제 구조 (2026-09 기준 main 브랜치)

| 사실 | 의미 |
|---|---|
| 저장소 **루트에 `setup.py` 가 없음** | main이 연구용 모노레포(`VPPV/`, `Benchmark/`, `Haptic_guidance/`, `Data_driven_scene_simulation/`)로 재편됨. 루트에서 `pip install -e .` 하면 **실패** |
| 고전 SurRoL 패키지 위치 | **`Benchmark/state_based/`** (여기에 `setup.py`, `surrol/`, `tests/` 가 있음) |
| `panda3d==1.10.11` 하드 핀 | **Python 3.11+ 휠이 없음**(1.10.12부터 제공). 그래서 **Python 3.10** 환경을 씁니다 |
| 태스크가 `MPM.mpm3d`(taichi), `matplotlib`, `trimesh` 임포트 | 최소 설치만으로는 일부 태스크가 안 돌 수 있음 |
| `gym>=0.15.6` + goal-env API | 2021년 API 기준. 최신 gym(0.26+)과 호환이 깨질 수 있음 |

### B-1. 설치

```bash
conda create -n surrol python=3.10 -y -c conda-forge --override-channels
conda activate surrol

mkdir -p ~/isaac-healthcare-sims && cd ~/isaac-healthcare-sims
git clone https://github.com/med-air/SurRoL.git

cd SurRoL/Benchmark/state_based        # ★ 루트가 아니라 여기!
pip install --upgrade pip
pip install -e .
```

`setup_local.sh --with-surrol` 도 위와 동일한 경로/버전으로 시도합니다(실패해도 핵심 셋업은 유지).

### B-2. 사용 가능한 태스크(환경 ID)

`surrol/gym/__init__.py` 에 등록된 것들:

| 로봇 | 환경 ID |
|---|---|
| PSM (단일 팔) | `NeedleReach-v0`, `NeedlePick-v0`, `GauzeRetrieve-v0`, `PegTransfer-v0` |
| PSM (양팔) | `NeedleRegrasp-v0`, `BiPegTransfer-v0` |
| ECM (내시경 카메라) | `ECMReach-v0`, `MisOrient-v0`, `StaticTrack-v0`, `ActiveTrack-v0` |

가장 단순한 것은 **`NeedleReach-v0`** (바늘까지 도달만 하면 되는 태스크)입니다.

### B-3. 가장 간단한 예제

```python
import gym
import surrol.gym          # 환경 등록(import 하는 것만으로 register 됨)

env = gym.make('NeedleReach-v0', render_mode='human')
obs = env.reset()
for _ in range(100):
    obs, reward, done, info = env.step(env.action_space.sample())  # 무작위 동작
    if done:
        obs = env.reset()
env.close()
```

저장소에 포함된 데모도 있습니다:
```bash
python tests/demo_multiple_scenes.py     # Benchmark/state_based/tests/ 안
```

> 막히면 **SurRoL README를 1순위**로 따르세요: https://github.com/med-air/SurRoL
> 더 현대적인 의존성을 원하면 **SurRoL-v2**(hding2455/SurRoL-v2)도 검토하세요.

## C. Isaac for Healthcare (i4h) 워크플로우

i4h는 **Docker 컨테이너**로 돌리는 게 기본이라 호스트의 Isaac Sim 버전과 충돌하지 않습니다.
```bash
mkdir -p ~/isaac-healthcare-sims && cd ~/isaac-healthcare-sims
git clone https://github.com/isaac-for-healthcare/i4h-workflows.git
cd i4h-workflows
./i4h run robotic_ultrasound full_pipeline --as-root
```
진입 순서, 요구사항(RTI DDS 라이선스, 방화벽), 데이터 수집→변환→파인튜닝→평가 분업은
[03-i4h-연결.md](03-i4h-연결.md)에 정리돼 있습니다.

## 자주 겪는 문제

| 증상 | 원인 | 해결 |
|---|---|---|
| `nvidia-smi` 없음 / GPU 미감지 | 원격·클라우드 컨테이너이거나 드라이버 미설치 | **실제 로컬 GPU PC**에서 실행. 드라이버 설치 |
| `CondaToSNonInteractiveError` (Terms of Service) | 최신 conda가 Anaconda 기본 채널 ToS 동의를 요구 | 스크립트는 **conda-forge 채널만** 써서 이미 우회함. 수동 생성 시 `conda create -n isaacsim python=3.11 -c conda-forge --override-channels` 로 만드세요 |
| `conda: command not found` (셋업 후 터미널에서) | conda가 셸 PATH에 아직 없음 | **새 터미널을 열거나** `source ~/.bashrc` 실행. 스크립트가 `conda init bash`를 걸어둡니다 |
| Isaac Sim `No matching distribution` | Python 버전 불일치 | `isaacsim`은 3.11. env를 3.11로 다시 생성 |
| SurRoL `pip install -e .` 실패 | 원본은 Python 3.7 + 구형 의존성 | `surrol` env가 3.7인지 확인. RL 스택은 SurRoL README 수동 절차 |
| 두 시뮬이 서로 깨짐 | 한 환경에 섞어 설치 | 반드시 **환경 분리**(`isaacsim` vs `surrol`) |
| GUI 실행 시 **"중단하기 / 기다리기"** 창이 계속 뜸 | 첫 실행의 확장 다운로드 + 셰이더 컴파일로 창이 응답하지 않아 OS가 멈춘 걸로 오해 | **"기다리기"를 누르세요**(10~30분). 중단하면 캐시가 미완성으로 남아 다음에도 느려집니다. 위 A-4의 헤드리스 예열을 먼저 하는 게 최선 |
| 진짜 진행 중인지 모르겠음 | — | 새 터미널에서 `nvidia-smi`(프로세스·사용률 확인), `du -sh ~/.cache/ov ~/.nvidia-omniverse`(용량이 커지면 정상), `tail -f ~/.nvidia-omniverse/logs/Kit/Isaac-Sim/*/kit_*.log` |
| 첫 실행 10분+ 멈춤 | 셰이더 캐시 컴파일 | 정상. 기다리면 다음부턴 빠름 |
