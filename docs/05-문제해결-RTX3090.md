> [04. i4h 설치 가이드](04-i4h-설치-RTX3090.md) 진행 중 막혔을 때 보세요.

## VRAM / OOM

### `CUDA out of memory` — 학습 시작 직후

`num_envs` 가 너무 큽니다. 절반으로 줄이세요.

```bash
./scripts/04_train_rl.sh --envs 512
```

실측이 안 되어 있다면:

```bash
./scripts/03_find_max_envs.sh
```

### 학습 중반에 OOM

시작은 됐는데 도중에 터진다면 **VRAM 여유가 5~10%밖에 없는 상태**입니다.
피크가 순간적으로 튀면서 넘어간 것입니다.

- 측정값의 80% 수준으로 낮추세요
- 학습 중 브라우저를 새로 열지 마세요

### VRAM이 이미 3~4GB 점유되어 있다

데스크탑 환경이 먹고 있습니다. 확인:

```bash
nvidia-smi --query-compute-apps=pid,process_name,used_memory --format=csv
```

해결 (효과 순):

1. **모니터를 내장 그래픽으로 이전** — BIOS에서 iGPU 활성화 후
   메인보드 HDMI/DP에 연결. 3090 VRAM 24GB를 온전히 확보
2. 학습 전 브라우저/IDE 종료
3. TTY 전환: `Ctrl+Alt+F3` → 로그인 → 학습 실행
   (돌아올 때는 `Ctrl+Alt+F2` 또는 `F1`)
4. 디스플레이 매니저 정지 (원격 접속 시에만):
   ```bash
   sudo systemctl stop gdm3     # GNOME
   ```

### `--headless` 인데도 VRAM을 많이 쓴다

`--headless` 는 화면 출력을 끄지만 물리 시뮬레이션 자체는 GPU에서 돕니다.
`num_envs` 에 비례해 늘어나는 건 정상입니다. 태스크에 변형체
(`lift_needle_organs`)가 포함되면 같은 `num_envs` 라도 훨씬 많이 씁니다.

## 디스크

### `No space left on device`

`robotic_surgery` 만으로 100GB를 요구합니다.

```bash
df -h
du -sh ~/i4h-workflows ~/.cache 2>/dev/null
```

정리 대상:

```bash
# Docker 이미지/캐시 (Conda 설치를 쓴다면 통째로 불필요)
docker system df
docker system prune -a          # 주의: 다른 이미지도 지워집니다

# pip / conda 캐시
pip cache purge
conda clean --all -y

# HuggingFace 캐시
du -sh ~/.cache/huggingface
```

**근본 대책**: `config/env.sh` 에서 여유 있는 파티션을 지정하세요.

```bash
export I4H_ROOT=/mnt/data/i4h-workflows
export OPENH_DATA_DIR=/mnt/data/open-h-embodiment
export HF_HOME=/mnt/data/hf-cache
```

### Docker vs Conda

디스크가 빠듯하면 **Conda 설치**를 쓰세요. i4h는 Docker가 기본이지만
컨테이너 이미지가 수십 GB를 추가로 먹습니다.

## 온도 / 성능

### 학습이 갈수록 느려진다

Thermal throttling 입니다. 확인:

```bash
./scripts/gpu_monitor.sh
```

83°C 부근에서 클럭이 떨어집니다. 대응:

```bash
sudo nvidia-smi -pl 300     # 전력 제한 350W -> 300W
```

성능 손실보다 온도 개선폭이 커서, 총 학습 시간이 오히려 줄어드는 경우가
많습니다. 원복은 `sudo nvidia-smi -pl 350`.

케이스 흡배기, GPU 먼지, 서멀패드 상태도 함께 확인하세요.

## 설치 단계

### `env_setup_robot_surgery.sh` 가 중간에 실패

- **네트워크 타임아웃**이 가장 흔합니다. 다시 실행하면 이어서 진행됩니다
- conda 환경이 오염됐다면 지우고 다시:
  ```bash
  conda env remove -n robotic_surgery
  ./scripts/01_install_robotic_surgery.sh
  ```

### `tools/env_setup_robot_surgery.sh: No such file`

저장소 구조가 바뀌었을 수 있습니다.
[robotic_surgery 워크플로](https://github.com/isaac-for-healthcare/i4h-workflows/tree/main/workflows/robotic_surgery)
에서 현재 설치 절차를 확인하세요.

### `ModuleNotFoundError` — 스크립트 실행 시

`PYTHONPATH` 가 안 잡혔습니다.

```bash
export PYTHONPATH=$I4H_ROOT/workflows/robotic_surgery/scripts:$PYTHONPATH
```

conda 환경도 확인:

```bash
conda activate robotic_surgery
python --version    # 3.11.x 여야 함
```

### 여러 워크플로를 한 환경에 설치했더니 깨졌다

i4h 워크플로마다 의존성이 다릅니다. **워크플로당 conda 환경 하나**가
원칙입니다. 섞였다면 환경을 지우고 다시 만드는 편이 빠릅니다.

## GUI / 표시

### 데모 실행 시 창이 안 뜬다

- SSH 접속 중이면 X11 포워딩이 필요합니다: `ssh -X`
- 또는 데스크탑에서 직접 실행하세요
- 학습은 어차피 `--headless` 라 창이 필요 없습니다

### 첫 실행이 너무 오래 걸린다

에셋 다운로드입니다. 5~10분이 정상입니다. 두 번째부터는 빠릅니다.

## Open-H-Embodiment

### `StreamingLeRobotDataset` import 실패

`lerobot >= 0.6.0` 이 필요합니다. 모듈 경로가 버전에 따라 다릅니다.

```bash
conda activate openh
pip install -U 'lerobot>=0.6.0'
python -c "import lerobot; print(lerobot.__version__)"
```

### 저장소를 열지 못한다 / 포맷이 안 맞는다

HuggingFace에 공개된 v1과 GitHub의 v2 스펙(LeRobot v3.0)이 다를 수
있습니다. 먼저 구조를 직접 확인하세요:

```bash
python tools/explore_openh.py           # 포맷 자동 판정
python tools/explore_openh.py --tree    # 실제 파일 목록
```

로그인이 필요한 경우:

```bash
hf auth login
```

### 다운로드가 디스크를 다 먹는다

전체를 받지 마세요. 항상 `--dry-run` 으로 용량을 먼저 확인하고,
서브셋 패턴으로 좁혀서 받으세요.

```bash
python tools/download_openh_subset.py --list
python tools/download_openh_subset.py --include '<패턴>' --dry-run
```
