## Ex11 — 공개 데이터셋 다루기

Isaac Sim이 **필요 없습니다.** 데이터셋은 시뮬레이터 확장이 아니라 그냥 파일입니다.

```bash
./scripts/10_install_openh.sh          # conda env "openh" (Python 3.12)
conda activate openh

cd exercises/ex11_public_dataset
python solution.py --test              # 먼저 짧게 — API 호환성 확인
python solution.py --episodes 20       # 본 실행
```

**하는 일**

1. Open-H-Embodiment를 **스트리밍으로** 연다 (780시간, 다운로드 없음)
2. 액션·상태 벡터의 각 차원이 무엇인지 **값 분포로 추론**한다
3. 궤적을 플롯해 눈으로 검증한다
4. Isaac PSM의 8차원 액션과 대응표를 만든다

**왜 스트리밍인가**: 780시간을 통째로 받으면 디스크가 감당하지 못합니다.
훑어보고 필요한 서브셋만 받는 게 표준 절차입니다.

**차원 추론이 핵심입니다.** 데이터셋 문서에 액션 정의가 없는 경우가 흔합니다.
`solution.py`의 `guess_semantics()`가 하는 판정:

| 신호 | 추정 |
|---|---|
| 4연속 성분의 norm이 1 | 쿼터니언 |
| 값이 −π~π 범위, 변동 큼 | 관절각 (rad) |
| 절댓값 1 미만, 연속적 | 위치 (m) 또는 정규화된 값 |
| 두세 값만 오감 | 그리퍼 |

> 이 판정은 **추정**입니다. 데이터셋 문서로 반드시 교차 확인하세요.

## Ex12 — 궤적을 Isaac Sim dVRK에 재생

```bash
conda activate robotic_surgery
export PYTHONPATH=$I4H_ROOT/workflows/robotic_surgery/scripts:$PYTHONPATH

cd exercises/ex12_trajectory_replay
python solution.py --synthetic circle --test        # API 확인
python solution.py --synthetic circle --gui         # 원 궤적 재생
```

### ★ 반드시 합성 궤적부터

실데이터로 바로 가지 마세요. 로봇이 안 움직일 때 **변환 버그인지 데이터
문제인지 구분할 수 없습니다.** `--synthetic circle`로 파이프라인을 먼저
검증한 뒤 실데이터를 붙이세요.

### 액션 규약 (i4h 실제 값)

```
actions[:, 0:3]  EE 위치 (x,y,z)       m, 베이스 프레임
actions[:, 3:7]  쿼터니언 (w,x,y,z)    ← wxyz 순서
actions[:, 7]    그리퍼                OPEN=+1.0 / CLOSE=-1.0
```

환경 ID: `Isaac-Reach-PSM-IK-Abs-v0`, `Isaac-Lift-Needle-PSM-IK-Abs-v0`,
`Isaac-Lift-Needle-PSM-IK-Rel-v0`

> `actions[:, 3] = 1.0`(단위 쿼터니언 w)을 빼면 **로봇이 아예 안 움직입니다.**
> 가장 흔한 실수입니다.

### 실데이터 붙이기

```bash
python solution.py --traj episode.npy \
  --pos-unit mm --quat-order xyzw --gripper-convention unit --gui
```

변환에서 실제로 어긋나는 항목들:

| 옵션 | 왜 필요한가 |
|---|---|
| `--pos-unit mm` | 데이터가 mm인데 Isaac은 m. **1000배 어긋남** |
| `--quat-order xyzw` | Isaac은 wxyz. 많은 데이터셋은 xyzw. **회전이 이상해짐** |
| `--gripper-convention` | `pm1`/`unit`(0..1)/`jaw_rad`(열림각) 제각각 |
| `--offset` | 좌표계 원점이 다름 |

## ⚠️ 이 실습의 결론은 "된다"가 아닙니다

Ex12 Part E에서 확인하게 될 것:

**실기기 궤적을 시뮬레이터에서 재생하면 팔은 같은 경로로 움직이지만,
접촉과 변형은 재현되지 않습니다.** 시뮬레이터의 장기 모델은 실제 돼지 간과
형상·물성이 다르기 때문입니다. 그리퍼가 닫히는 타이밍에 니들이 잡히지
않아도 **정상입니다.**

즉 이건 **동작 재현(kinematic replay)** 이지 물리 재현이 아닙니다.

그래서 실기기 데이터의 올바른 쓰임새는 시뮬레이터 재생이 아니라
**정책 학습 입력**입니다. [docs/06](06-데이터셋-Isaac-Sim-호환성.md)의
L2 / L3 구분과 권장 파이프라인 절을 보세요.

## 검증 상태

- **Ex11**: 스키마 추론·플롯·호환성 판정 로직을 합성 데이터 9개 케이스로
  검증했습니다. 실제 Open-H-Embodiment를 내려받아 돌려보지는 못했습니다
  (이 환경에서 HuggingFace 접속이 차단됨).
- **Ex12**: 순수 계산부(단위 변환, 쿼터니언 재배열·정규화·slerp, 리샘플링,
  워크스페이스 클리핑, 오차 계산)를 30여 개 단위 테스트로 검증했습니다.
  **시뮬레이션 루프는 실행 검증하지 못했습니다** — i4h의 공개 state machine
  스크립트에서 확인한 API를 기준으로 작성했습니다.

두 과제 모두 `--test` 플래그로 먼저 짧게 돌려 API 호환성을 확인한 뒤
본 실행으로 넘어가세요. 어긋나는 부분이 있으면 그것을 고치는 것 자체가
실습의 일부입니다.
