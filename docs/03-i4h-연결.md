# 03. Isaac for Healthcare로 넘어가기

Ex01~10을 끝냈다면 이제 실제 의료 워크플로우로 들어갈 준비가 된 것입니다.
여기서는 **i4h가 무엇으로 구성되어 있고, 어떤 순서로 들어가야 안 헤매는지**를 정리합니다.

---

## 1. Isaac for Healthcare란

NVIDIA가 의료 로보틱스 전용으로 제공하는 **레퍼런스 워크플로우 모음**입니다.
Isaac Sim / Isaac Lab 위에 얹혀 있고, 저장소는
[`isaac-for-healthcare/i4h-workflows`](https://github.com/isaac-for-healthcare/i4h-workflows) (Apache-2.0)입니다.

"프레임워크"라기보다 **완성된 엔드투엔드 예제 7개**라고 이해하는 게 정확합니다.
각 워크플로우는 `디지털 트윈 씬 → 데이터 수집 → 정책 학습 → 배포`까지 한 벌로 들어 있습니다.

### 워크플로우 7종 (v0.7.0 기준)

| 워크플로우 | 디렉터리 | 내용 | 난이도 |
|---|---|---|:--:|
| **SO-ARM Starter** | `workflows/so_arm_starter/` | SO-ARM101 매니퓰레이터로 수술 도구 핸들링. GR00T N1.5 디퓨전 정책, 듀얼 RGB 카메라(640×480@30fps) | ⭐ 입문 |
| **Robotic Ultrasound** | `workflows/robotic_ultrasound/` | GPU 레이트레이싱 기반 초음파 물리 시뮬레이션, B-mode 영상 생성, PI0/GR00T N1 정책 | ⭐⭐ |
| **Robotic Surgery** | `workflows/robotic_surgery/` | dVRK, 듀얼암, STAR 수술 로봇. 봉합침 조작·정밀 도달 서브태스크, GPU 병렬 RL | ⭐⭐ |
| **Telesurgery** | `workflows/telesurgery/` | 원격 수술. H.264/HEVC 하드웨어 인코딩, 햅틱 피드백, RTI DDS, x86/AARCH64 | ⭐⭐⭐ |
| **Rheo** | `workflows/rheo/` | 스마트 병원 디지털 트윈. GR00T VLA 물리 에이전트 + VLM 디지털 에이전트, 변형체(천) 시뮬 | ⭐⭐⭐ |
| **Agentic** | `workflows/agentic/` | IsaacLab-Arena 기반 에이전틱 태스크. SO-ARM 101 / Unitree G1 / Franka, 11개 등록 환경 | ⭐⭐⭐ |
| **Endoluminal (Catheter Navigation)** | `workflows/catheter_navigation/` | 혈관 내 카테터/가이드와이어 내비게이션. Slang DRR 형광투시 렌더러 + XPBD Cosserat rod 솔버, 환자별 혈관 디지털 트윈 | ⭐⭐⭐⭐ |

## 2. 어떤 순서로 들어가야 하나

```
Ex01~10 완주
   │
   ├─▶ ① SO-ARM Starter  ── 가장 단순. 데이터 수집 → 학습 → 추론 전체 루프를 최소 규모로 경험
   │
   ├─▶ ② Robotic Ultrasound ── "healthcare"의 핵심. 초음파 물리 시뮬 + 정책 제어
   │        └─ 여기서 여러분의 팬텀/장기 에셋으로 교체해보기  ← Ex08, Ex10의 결과물 활용
   │
   ├─▶ ③ Robotic Surgery ── dVRK 등 실제 수술 로봇 기구학. RL 학습 관심 있으면
   │
   └─▶ ④ 나머지 (Telesurgery / Rheo / Agentic / Endoluminal)
            └─ 각각 DDS·네트워크·VLM·CT 파이프라인 등 추가 도메인 지식 필요
```

**첫 목표를 "Robotic Ultrasound 파이프라인 1회 완주"로 잡으세요.**
멋있어 보이는 Telesurgery부터 시작하면 RTI DDS 라이선스, 방화벽, 두 대의 머신 등
로보틱스와 무관한 인프라 문제로 며칠을 씁니다.

## 3. Robotic Ultrasound 첫 실행

```bash
git clone https://github.com/isaac-for-healthcare/i4h-workflows.git
cd i4h-workflows

# 전체 파이프라인 (Isaac Lab 씬 + PI0 정책 + DearPyGUI 시각화)을 컨테이너에서 실행
./i4h run robotic_ultrasound full_pipeline --as-root
```

**무슨 일이 일어나나**
- Isaac Sim이 병원 침대 + 환자 모델 + Franka 팔 씬을 띄웁니다.
- PI0(또는 GR00T N1) 신경망이 카메라 입력을 보고 스캔 동작을 자율 생성합니다.
- 별도 창에 실시간 B-mode 초음파 영상이 뜹니다.
- 프로세스 간 통신은 RTI DDS로 이뤄집니다.

**주의사항**
- 최초 컨테이너 빌드 **10분 이상**, 이후 실행도 Isaac Lab 초기화에 **2분 이상**.
  초기화 중 창이 멈춘 것처럼 보여도 정상입니다.
- 반드시 **root로 실행**(`--as-root`)해야 Isaac Sim/Lab 권한 에러를 피합니다.
- RTI Connext DDS **평가 라이선스**가 필요합니다.

유용한 CLI:
```bash
./i4h run robotic_ultrasound --help      # 이 워크플로우의 모든 모드 보기
./i4h run robotic_ultrasound <mode> --dry-run   # 실행 없이 명령만 출력
./i4h run robotic_ultrasound <mode> --verbose
```

## 4. 이 과제집의 어느 부분이 i4h의 무엇에 대응하나

| 이 과제집 | i4h에서 대응되는 것 |
|---|---|
| Ex01~02 (씬/USD/물리) | 각 워크플로우의 `sim/` 씬 정의, 팬텀·침대·장기 에셋 배치 |
| Ex03 (아티큘레이션) | Franka / SO-ARM101 / dVRK PSM 로봇 제어 |
| Ex04 (카메라) | room view / wrist view 듀얼 RGB 카메라 스트림 |
| Ex05 (IK·궤적) | 스캔 프로토콜, `state machine` 기반 자동 데이터 수집 |
| Ex06 (접촉력) | 프로브-피부 접촉 유지, 안전 정지 조건 |
| Ex07 (Replicator SDG) | 합성 학습 데이터 생성, 도메인 랜덤화 |
| Ex08 (커스텀 에셋) | "bring your own patient" — CT/MRI에서 만든 자기 팬텀 투입 |
| Ex09 (클로닝) | Isaac Lab의 GPU 병렬 RL 환경 |
| Ex10 (캡스톤 로깅) | HDF5 → LeRobot 포맷 변환 → PI0/GR00T 파인튜닝 |

즉 **Ex10 캡스톤의 출력 형식(HDF5 궤적 + 이미지)이 i4h 학습 파이프라인의 입력 형식**과
같은 역할을 합니다. i4h에서는 이걸 LeRobot 포맷으로 변환해 정책을 파인튜닝합니다.

```bash
# i4h의 전형적인 학습 흐름
# 1) 데이터 수집 (텔레오퍼레이션 또는 상태기계)   ← 24GB GPU에서 가능 (RTX 3090 등)
# 2) HDF5 → LeRobot 변환                          ← CPU 작업, GPU 무관
# 3) PI0 또는 GR00T N1 파인튜닝                    ← 48GB 권장, 클라우드 GPU 권장
# 4) 시뮬레이션에서 평가                           ← 24GB GPU에서 가능
```

> **24GB GPU(RTX 3090/4090) 사용자를 위한 분업**: 1·2·4단계(데이터 수집·변환·평가)는
> 24GB에서 됩니다. **3단계 파인튜닝만** VRAM이 부족합니다. 이 단계만 클라우드
> (RunPod / Lambda / AWS의 A6000 48GB · L40S · H100 등)로 넘기면 됩니다.
> 데이터셋(수 GB의 HDF5)만 업로드하면 되므로 워크플로우가 크게 끊기지 않습니다.
> 학습이 끝난 체크포인트를 내려받아 다시 로컬 3090에서 평가·배포하는 흐름입니다.

## 5. i4h를 읽을 때의 독해 팁

1. **`workflows/<이름>/README.md`부터 끝까지 읽으세요.** 요구사항·모드·CLI가 다 있습니다.
2. **`./i4h run <workflow> --help`로 모드 목록을 확인**하고, `--dry-run`으로
   실제 어떤 파이썬 스크립트가 실행되는지 보세요. 그 스크립트가 진입점입니다.
3. **Isaac Lab 환경 정의**(`*_env_cfg.py`)를 찾으세요. 로봇, 씬, 관측, 보상,
   종료 조건이 전부 여기 선언되어 있습니다. 이 파일 하나가 워크플로우의 설계도입니다.
4. **DDS 토픽 정의**를 보면 프로세스 간 데이터 흐름(관측/액션/영상)이 보입니다.

## 6. 실제 하드웨어로 넘어갈 때

Robotic Ultrasound는 시뮬레이션과 실물 하드웨어를 섞어 돌릴 수 있습니다.

- **Clarius Cast / Solum** 초음파 프로브
- **Intel RealSense** 뎁스 카메라

시뮬레이션에서 검증한 정책을 그대로 실물 프로브 영상에 물려볼 수 있어서,
sim-to-real 갭 측정에 유용합니다.
